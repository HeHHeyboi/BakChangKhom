## 4. Phase 0 — Sub-minigame วินิจฉัย: "ทำไมต้องดูแรม"

### 4.1 กติกา

หน้าจอแสดง **คอมของลูกค้า** ที่เปิดอยู่ ผู้เล่นคลิกสำรวจ **จุดสังเกต 3 จุด** จากนั้นเลือกสาเหตุจาก 4 ตัวเลือก

**จุดสังเกต (ต้องคลิกครบทั้ง 3 ก่อนถึงจะเลือกสาเหตุได้):**

| #   | จุด         | สิ่งที่ผู้เล่นเห็น/ได้ยิน            | เบาะแสที่ได้                            |
| --- | ----------- | ------------------------------------ | --------------------------------------- |
| 1   | หน้าจอ      | จอฟ้า/จอค้างเป็นบล็อกสี ขึ้น ๆ ดับ ๆ | ระบบล้มระหว่างทำงาน ไม่ใช่เปิดไม่ติดเลย |
| 2   | ลำโพงเคส    | เสียงบี๊บสั้น ๆ ซ้ำ ๆ ตอนเปิดเครื่อง | รหัส POST ฟ้องหน่วยความจำ               |
| 3   | ในเคส (ซูม) | ฝุ่นจับหนาที่แผงแรม ขาทองหมอง        | มีคราบออกไซด์/ฝุ่นที่หน้าสัมผัส         |

> คลิกแล้วปิ๊บพูด 1 ประโยคต่อจุด และเบาะแสถูกจดลง **"สมุดจดอาการ"** มุมขวาบน (3 ช่อง)

### 4.2 ตัวเลือกสาเหตุ

| ตัวเลือก               | ผลลัพธ์                                                                       |
| ---------------------- | ----------------------------------------------------------------------------- |
| A. จอภาพเสีย           | ❌ ปิ๊บ: "ถ้าจอเสีย จะไม่มีเสียงบี๊บตอนบูตนะขม"                                |
| B. **แรมหลวม/ขาสกปรก** | ✅ ถูกต้อง → ไป Phase 1                                                        |
| C. ไฟไม่พอ (PSU)       | ❌ ปิ๊บ: "ถ้าไฟไม่พอ เครื่องจะดับทั้งเครื่องเลย ไม่ใช่ค้างแบบนี้"              |
| D. ไวรัส               | ❌ ปิ๊บ: "ไวรัสไม่ทำให้มีเสียงบี๊บตอนบูตหรอก เสียงบี๊บมาก่อนระบบจะโหลดเสียอีก" |

**กติกาตอบผิด:** ตอบผิดได้ไม่จำกัด ไม่มีบทลงโทษรุนแรง — แต่ละครั้งปิ๊บอธิบายว่าทำไมไม่ใช่ (เรียนรู้จากความผิดพลาด ไม่ใช่ลงโทษ) และหักคะแนนความแม่นยำ (หัวข้อ 9)

**ถ้าตอบผิดครบ 3 ครั้ง:** ปิ๊บใบ้ตรง ๆ — "ลองย้อนดูเบาะแสข้อ 2 กับ 3 สิ ทั้งคู่ชี้ไปที่ของชิ้นเดียวกันเลยนะ"

### 4.3 บทปิ๊บ Phase 0

```
ปิ๊บ,เครื่องนี้ลูกค้าบอกว่า "ใช้ ๆ อยู่แล้วค้าง" แต่เราจะเชื่อคำบอกเล่าอย่างเดียวไม่ได้
ปิ๊บ,ช่างที่ดีต้องดูอาการเองก่อน ลองคลิกดูทั้งสามจุดสิ แล้วค่อยสรุปว่าเกิดจากอะไร

# เมื่อคลิกจุดที่ 1 (หน้าจอ)
ปิ๊บ,เห็นมั้ย จอขึ้นเป็นบล็อกสีแล้วค้าง แปลว่าเครื่องบูตผ่านไปได้ระดับหนึ่งแล้วค่อยล้ม
ปิ๊บ,ถ้าเป็นจอเสียจริง ๆ เราจะไม่เห็นอะไรเลยตั้งแต่แรก

# เมื่อคลิกจุดที่ 2 (ลำโพงเคส)
ปิ๊บ,ได้ยินเสียงบี๊บสั้น ๆ ซ้ำ ๆ มั้ย นั่นคือเมนบอร์ดกำลังรายงานผลตรวจตัวเองตอนเปิดเครื่อง
ปิ๊บ,เขาเรียกว่ารหัส POST ส่วนใหญ่รูปแบบบี๊บซ้ำ ๆ แบบนี้หมายถึงหน่วยความจำมีปัญหา

# เมื่อคลิกจุดที่ 3 (ในเคส)
ปิ๊บ,ดูตรงแผงแรมสิ ฝุ่นจับหนาเลย แล้วขาสีทองด้านล่างก็หมองไม่วาว
ปิ๊บ,ขาทองพวกนี้แหละคือทางที่ข้อมูลวิ่งผ่าน ถ้ามีฝุ่นหรือคราบมาคั่น สัญญาณก็ไปไม่ถึง

# ตอบถูก
ปิ๊บ,ถูกต้อง! เบาะแสทั้งสามชี้ไปทางเดียวกันหมด — แรมหน้าสัมผัสไม่ดี
ปิ๊บ,นี่คือวิธีคิดของช่างนะขม ไม่ใช่เดา แต่เก็บอาการหลาย ๆ อย่างมาประกอบกัน
```

## 5. Phase 1 — BRIEFING: ปิ๊บสอนความรู้

ปิ๊บลอยเข้ามาข้างจอ พร้อมภาพประกอบเล็ก ๆ (`ram_diagram_*.png`) ผู้เล่นกด "ถัดไป" ทีละประโยค

```
ปิ๊บ,ก่อนลงมือ ขมรู้มั้ยว่าแรมคืออะไร
ปิ๊บ,แรมคือที่พักงานชั่วคราวของคอม เหมือนโต๊ะทำงาน ยิ่งโต๊ะใหญ่ก็ยิ่งวางของได้เยอะ
ปิ๊บ,แต่ถ้าขาที่เสียบต่อกับเมนบอร์ดสกปรก ข้อมูลก็วิ่งผ่านไม่สะดวก เครื่องเลยค้างหรือรีสตาร์ตเอง
ปิ๊บ,ขาสีทองด้านล่างเรียกว่า gold contact เป็นทองจริง ๆ นะ เพราะทองไม่เป็นสนิม
ปิ๊บ,แต่ฝุ่นกับความชื้นก็ยังเกาะได้ โดยเฉพาะบ้านเราที่อากาศชื้นและมีฝุ่นเยอะ
ปิ๊บ,เพราะงั้นงานแรกของช่างคือ ถอดออกมา ทำความสะอาด แล้วใส่กลับให้แน่น
ปิ๊บ,แต่ห้ามใจร้อนนะ มีเรื่องความปลอดภัยต้องทำก่อน ตามมาเลย

### Phase 3 · REMOVE (ถอดแรม)

1. คลิก **สลักล็อกซ้าย** → สลักกางออก (`ram_clip_left_open.png`)
2. คลิก **สลักล็อกขวา** → สลักกางออก

**เงื่อนไขผิด:**

* ลากแรมทั้งที่สลักยังปิดอยู่ → แรมสั่นแล้วเด้งกลับ + ปิ๊บ: "ดึงไม่ออกหรอก ต้องปลดสลักทั้งสองข้างก่อน ฝืนดึงขาหักได้เลยนะ"
* ลากเอียง (แกน x เบี่ยง > 40 px) → ปิ๊บ: "ดึงขึ้นตรง ๆ นะ งัดข้างเดียวขาแรมงอได้"

ปิ๊บ,เห็นสลักสีขาวสองข้างมั้ย นั่นคือตัวล็อกแรมไว้กับสลอต
ปิ๊บ,กดให้มันกางออกทั้งสองข้างพร้อมกัน แล้วแรมจะเด้งขึ้นมาเองนิดนึง
ปิ๊บ,จับที่ขอบบนของแผ่นนะ อย่าจับโดนขาทองหรือชิปดำ ๆ เหงื่อจากมือเราก็เป็นคราบได้
```

### Phase 4 · CLEAN (ขัด — ขยายเป็นระบบเลือกอุปกรณ์)

Phase นี้ถูกออกแบบใหม่เป็น **3 ขั้นย่อย ที่ต้องเลือกอุปกรณ์ให้เหมาะกับงาน** — รายละเอียดเต็มอยู่ใน **หัวข้อ 14**
สรุปสั้น: ปัดฝุ่นบนแผง → ขัดคราบที่ขาทอง → ทำความสะอาดสลอต โดยแต่ละขั้นมีอุปกรณ์ที่เหมาะ/พอใช้/ห้ามใช้ต่างกัน

กลไกการถู (ยางลบ lerp ซ้าย↔ขวา ตามจำนวนคลิก) ยังใช้ของเดิม แต่แก้ 3 อย่าง:

| เดิม                          | ใหม่                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| `match clikTime` เทียบค่าเป๊ะ | `if clikTime >= CLEAN` / `>= BETTER` (แก้ B4)                                              |
| ไม่มี feedback ระหว่างขัด     | แถบความสะอาด 0–100% + ฝุ่นฟุ้งเป็น particle ทุกครั้งที่ถู                                  |
| ขัดเกินก็ไม่เป็นไร            | **ขัดเกิน 22 ครั้ง → ปิ๊บเตือน** "พอแล้วขม ถูแรงเกินไปขาทองบางลงได้นะ" (ไม่หักคะแนนรอบแรก) |

### Phase 5 · INSTALL (ใส่กลับ)

1. **ลากแรมกลับมาเหนือสลอต** — ระบบเช็คว่าร่องบาก (notch) ตรงกับสันในสลอตหรือยัง
   * ถ้ากลับด้าน → แรมเป็นสีแดงจาง ๆ วางไม่ลง + ปิ๊บ: "กลับด้านแล้ว ดูร่องบากตรงกลางสิ มันไม่ตรงกับสันในสลอต"
2. **กดลง** (คลิกค้างหรือคลิกซ้ำ 2 ครั้ง) → สลักสองข้างดีดกลับเข้าที่เอง + เสียง *คลิก*

## 14. Phase 4 แบบขยาย — ระบบเลือกอุปกรณ์ทำความสะอาด

### 14.1 ทำไมต้องมีระบบนี้

ถ้าเกมยื่นยางลบให้แล้วบอก "ถูเลย" ผู้เล่นจะจำได้แค่ *ท่า* ไม่ได้เข้าใจ *เหตุผล*
ระบบนี้เปลี่ยนคำถามจาก "ถูยังไง" เป็น **"ทำไมต้องใช้ของชิ้นนี้ ไม่ใช่ชิ้นนั้น"** ซึ่งเป็นความรู้ที่เอาไปใช้กับงานซ่อมอื่นได้จริง

หลักการออกแบบ 3 ข้อ:

1. **ไม่มีคำตอบถูกข้อเดียว** — แต่ละขั้นย่อยมีอุปกรณ์ที่เหมาะต่างกัน อุปกรณ์ที่ดีสำหรับขั้นหนึ่งอาจห้ามใช้ในอีกขั้น
2. **ตัดสินจากคุณสมบัติ ไม่ใช่ท่องจำ** — ทุกชิ้นมีการ์ดคุณสมบัติให้ดูก่อนเลือก ผู้เล่นที่อ่านการ์ดเป็นจะเลือกถูกแม้เจออุปกรณ์ที่ไม่เคยเห็น
3. **ผิดแล้วได้เรียน ไม่ใช่ผิดแล้วแพ้** — เลือกผิดครั้งแรกปิ๊บห้ามทัน ไม่เกิดความเสียหายจริง

### 14.7 สเปกโค้ด (data-driven)

```gdscript
# Scripts/Resources/clean_tool.gd
class_name CleanTool extends Resource

enum Fit { FORBIDDEN, LIMITED, IDEAL }   # ❌ / 🟡 / ✅

@export var id: StringName                      # "eraser_white"
@export var display_name: String                # "ยางลบสีขาว"
@export var icon: Texture2D
@export_range(0, 5) var hardness: int = 0
@export var has_moisture: bool = false
@export var esd_risk: bool = false
@export var leaves_residue: bool = false
@export var reaches_narrow: bool = false
@export var fit_per_step: Dictionary[int, Fit] = {}   # CleanStep -> Fit
@export_multiline var line_ideal: String = ""
@export_multiline var line_limited: String = ""
@export_multiline var line_forbidden: String = ""
```

```gdscript
# Scripts/MiniGame/phase_clean.gd
enum CleanStep { DUST_BOARD, SCRUB_CONTACTS, CLEAN_SLOT }   # S1 S2 S3

signal step_completed(step: CleanStep)
signal clean_finished(penalty: int)

const TRAY_SIZE := 6
var _tools: Array[CleanTool]          # โหลดจาก Resources/MiniGame/Tools/*.tres
var _blocked_once: Dictionary = {}    # tool_id -> true (เลือก ❌ ไปแล้วรอบหนึ่ง)

func _build_tray(step: CleanStep) -> Array[CleanTool]:
    # การันตี ✅ ≥ 1 และ ❌ ≥ 2 แล้วสุ่มที่เหลือให้ครบ TRAY_SIZE
    ...

func _on_tool_used(tool: CleanTool, step: CleanStep) -> void:
    match tool.fit_per_step.get(step, CleanTool.Fit.FORBIDDEN):
        CleanTool.Fit.IDEAL:    _progress(step, 1.0); Pib.say([tool.line_ideal], PibHint.Mood.HAPPY)
        CleanTool.Fit.LIMITED:  _progress(step, 0.5); Pib.say([tool.line_limited], PibHint.Mood.NORMAL)
        CleanTool.Fit.FORBIDDEN:
            if _blocked_once.has(tool.id): _apply_damage(step, tool)
            else: _blocked_once[tool.id] = true
            Pib.say([tool.line_forbidden], PibHint.Mood.WORRY)
```

> โครงนี้ใช้ซ้ำได้กับ Core Part อีก 4 ตัว (เช่น เลือกซิลิโคนถูกชนิด, เลือกไขควงถูกหัว) — ออกแบบให้ `CleanStep` เป็น `int` จึงขยายเป็น step ของ Part อื่นได้
