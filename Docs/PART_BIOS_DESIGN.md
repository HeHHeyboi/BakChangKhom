## 1. ความรู้ที่ Part นี้สอน

| หัวข้อ | สิ่งที่ผู้เล่นต้องเข้าใจหลังเล่นจบ |
|---|---|
| BIOS/UEFI คืออะไร | โปรแกรมในเมนบอร์ดที่ทำงานก่อน Windows — ใช้ตรวจว่าฮาร์ดแวร์ครบมั้ย |
| อ่านหน้าจอ BIOS | ดูว่าเห็นแรมกี่ GB · เห็นดิสก์กี่ลูก · อุณหภูมิเท่าไร |
| Boot order | เครื่องไล่หาระบบปฏิบัติการตามลำดับที่ตั้งไว้ · บูตผิดลูกคือเข้าเครื่องไม่ได้ |
| XMP / EXPO | แรมวิ่งความเร็วต่ำกว่าที่เขียนข้างกล่อง จนกว่าจะเปิดโปรไฟล์นี้ |
| ลง OS | ต้องมี USB ที่ทำเป็นตัวติดตั้ง · เลือกไดรฟ์ให้ถูก ไม่งั้นข้อมูลลูกค้าหาย |
| Bottleneck | อัปเกรดต้องดูว่าชิ้นไหนคือคอขวด ไม่ใช่ซื้อของแพงสุด |

**เคสลูกค้า:** C05 "เปิดทีไรเข้าหน้าจอฟ้า ๆ ตัวหนังสือภาษาอังกฤษ"
คำสำคัญ: เข้า BIOS ทุกครั้ง · เพิ่งเสียบ USB ทิ้งไว้ · แรมเพิ่งเพิ่ม

## 2. Flow 8 Phase

```
0 INSPECT      อ่านหน้าจอ BIOS ที่ค้างอยู่ — หาว่าทำไมมันไม่ไปต่อ
1 BRIEFING     ปิ๊บสอน: BIOS คืออะไร ทำไมเครื่องถึงมาหยุดตรงนี้
2 CHECK_HW     ไล่ดูว่า BIOS เห็นฮาร์ดแวร์ครบมั้ย (แรม / ดิสก์ / พัดลม)
3 BOOT_ORDER   จัดลำดับการบูตใหม่  ← สาเหตุหลักของเคสนี้
4 XMP          เปิดโปรไฟล์ความเร็วแรม แล้วดูผลต่างก่อน–หลัง
5 SAVE_EXIT    บันทึกแล้วออก (เลือกให้ถูกระหว่าง Save / Discard / Load Default)
6 OS_INSTALL   (ถ้าดิสก์ไม่มีระบบ) ลง OS จาก USB — เลือกไดรฟ์ให้ถูก
7 UPGRADE      อ่านกราฟ bottleneck แล้วแนะนำลูกค้าว่าควรอัปเกรดอะไร → SUMMARY
```

**เวลาเล่น:** รอบแรก 6–8 นาที · รอบซ้ำ 2–3 นาที
Part นี้เป็น **Part เดียวที่ไม่ต้องถอดอะไร** — เล่นบนหน้าจอ BIOS ทั้งหมด

## 3. Phase 0 · INSPECT — อ่านหน้าจอที่ค้างอยู่

หน้าจอ BIOS แสดงข้อมูลจริง ผู้เล่นคลิก 3 จุด

| จุด | สิ่งที่เห็น | ตีความ |
|---|---|---|
| แถบ Boot Priority | อันดับ 1 คือ `USB: KINGSTON` | เครื่องพยายามบูตจาก USB ที่ลูกค้าเสียบค้างไว้ |
| แถบ Memory | `16384 MB · 2133 MHz` ทั้งที่แรมเขียนข้าง 3200 | XMP ยังไม่เปิด |
| แถบ Storage | `SATA 1: WDC 1TB` มีอยู่ปกติ | ดิสก์ไม่ได้เสีย ระบบยังอยู่ครบ |

สรุปได้เอง: **ไม่ใช่เครื่องพัง แค่บูตผิดลำดับ**

---

## 4. Phase 3 · BOOT_ORDER — ลากเรียงลำดับ

รายการ 4 อัน ลากสลับได้ (`bios_boot_order_item.png`)

| ลำดับที่จัด | ผล |
|---|---|
| `SSD/HDD ที่มี Windows` → `USB` → `DVD` → `Network` | ✅ ถูกต้อง |
| ปล่อย `USB` ไว้อันดับ 1 | ❌ ออกจาก BIOS แล้ววนกลับมาที่เดิม → ปิ๊บบอกให้สังเกตว่าเกิดอะไรซ้ำ |
| เอา `Network` ขึ้นอันดับ 1 | ❌ ค้างที่หน้าจอ PXE นาน ๆ แล้วค่อยไปต่อ — ปิ๊บอธิบายว่าบูตผ่านเน็ตใช้ในองค์กร |
| ถอด USB ออกแล้วไม่แก้ลำดับ | 🟡 เครื่องบูตได้ **แต่ปัญหาจะกลับมาทันทีที่ลูกค้าเสียบ USB อีก** −8 และปิ๊บย้ำว่านี่คือแก้ปลายเหตุ |

> จุดสอนสำคัญของ Part นี้: **แก้ที่ต้นเหตุ ไม่ใช่แค่ทำให้มันหายตอนนี้**

---

## 5. Phase 4 · XMP — เปิดโปรไฟล์ความเร็วแรม

| การกระทำ | ผล |
|---|---|
| เปิด XMP Profile 1 | ✅ แถบ Memory เปลี่ยนเป็น 3200 MHz + ปิ๊บอธิบายว่าทำไมค่าเริ่มต้นถึงต่ำ |
| ไม่เปิด | 🟡 ผ่านได้ แต่เสียโอกาส −5 และหน้าสรุปจะบอกว่าลูกค้าจ่ายค่าแรมเร็วแต่ไม่ได้ใช้ |
| เปิดแล้วเครื่องบูตไม่ขึ้น (สุ่ม 20%) | ต้องแก้โดย **เคลียร์ CMOS** (ถอดถ่าน 10 วิ) แล้วลองโปรไฟล์ 2 หรือปล่อยไว้ — สอนว่า XMP คือการโอเวอร์คล็อกอย่างหนึ่ง ไม่การันตี 100% |

---

## 6. Phase 5 · SAVE_EXIT — เลือกให้ถูก

| ตัวเลือก | ผล |
|---|---|
| Save Changes and Exit | ✅ |
| Discard Changes and Exit | ❌ ทุกอย่างที่ทำมาหายหมด ต้องทำใหม่ (เสียเวลา ไม่มีอะไรพัง) |
| Load Optimized Defaults แล้ว Save | 🟡 ค่าที่ตั้งหายแต่เครื่องกลับมาปกติ — ปิ๊บบอกว่านี่คือปุ่มช่วยชีวิตตอนตั้งค่ามั่วจนบูตไม่ขึ้น |

---

## 7. Phase 6 · OS_INSTALL — เลือกไดรฟ์ให้ถูก

เข้าเฉพาะกรณีที่ดิสก์ไม่มีระบบ (เคสอื่น ๆ ข้าม phase นี้)

| ตัวเลือกไดรฟ์ | ผล |
|---|---|
| `SSD 240GB (ว่าง)` | ✅ ถูกต้อง — ลง OS ลง SSD เร็วกว่า |
| `HDD 1TB (มีข้อมูลลูกค้า)` | ❌ **ปิ๊บหยุดมือไว้ก่อน** — อธิบายว่าฟอร์แมตทับคือข้อมูลลูกค้าหายถาวร · ถ้ายืนยันซ้ำ = จบงานแบบชื่อเสียงติดลบ |
| `USB ตัวติดตั้งเอง` | ❌ ลงทับตัวติดตั้งไม่ได้ |

**ระหว่างติดตั้ง:** แถบ `bios_progress_bar.png` เดิน ~10 วินาที · ปิ๊บใช้ช่วงนี้เล่าเรื่องการสำรองข้อมูล

## 8. Phase 7 · UPGRADE — อ่านกราฟ bottleneck

กราฟแท่งเทียบ CPU / GPU / RAM / Storage ของเครื่องลูกค้า

| ผู้เล่นแนะนำ | ผล |
|---|---|
| ชิ้นที่แท่งต่ำสุด (คอขวดจริง) | ✅ +10 · ลูกค้าพอใจ |
| ชิ้นที่แพงที่สุด | ❌ ปิ๊บเตือนว่าอัปแล้วไม่เร็วขึ้น เพราะคอขวดอยู่อีกที่ |
| "ไม่ต้องอัปอะไร ใช้แบบนี้พอ" | ✅ ถ้าทุกแท่งสมดุลอยู่แล้ว — เป็นคำตอบที่ถูกในบางเคส |

> สอนตรง ๆ ว่า **การบอกลูกค้าว่า "ยังไม่ต้องซื้อ" ก็เป็นคำตอบที่ถูกได้** และทำให้ลูกค้ากลับมาอีก

## 9. บทปิ๊บ (`Assets/Dialog/MiniGame/Bios_Pib.txt`)

```
# Phase 1 BRIEFING
ปิ๊บ,หน้าจอฟ้า ๆ นี่ไม่ใช่เครื่องพังนะขม มันคือ BIOS โปรแกรมที่อยู่ในเมนบอร์ด
ปิ๊บ,ทุกครั้งที่เปิดเครื่อง BIOS จะทำงานก่อน Windows เสมอ คอยตรวจว่าฮาร์ดแวร์ครบมั้ย
ปิ๊บ,ที่มันมาค้างตรงนี้แปลว่ามันหาระบบปฏิบัติการไม่เจอ ไม่ใช่ว่าดิสก์เสีย

# Phase 2 ตรวจฮาร์ดแวร์
ปิ๊บ,ดูแถบ Memory ก่อน เห็นมั้ยว่าขึ้น 16 GB ครบตามที่ลูกค้าบอก
ปิ๊บ,แล้วก็ SATA 1 เห็นฮาร์ดดิสก์อยู่ แปลว่าดิสก์ไม่ได้หาย ระบบน่าจะยังอยู่

# Phase 3 boot order
ปิ๊บ,ตรงนี้แหละคือต้นเหตุ — อันดับหนึ่งของการบูตคือ USB ที่ลูกค้าเสียบทิ้งไว้
ปิ๊บ,เครื่องมันเชื่อฟังเราเป๊ะ ๆ เราบอกให้หาจาก USB ก่อน มันก็หาจาก USB แล้วไม่เจอระบบ เลยค้าง
ปิ๊บ,ถอด USB ออกเฉย ๆ ก็หายนะ แต่พอลูกค้าเสียบอีกก็เป็นอีก เราแก้ที่ลำดับดีกว่า

# Phase 4 XMP
ปิ๊บ,แรมกล่องนี้เขียนว่า 3200 แต่ BIOS ขึ้นแค่ 2133 — ไม่ได้โดนหลอกนะ
ปิ๊บ,ค่ามาตรฐานมันตั้งไว้ต่ำเพื่อให้ทุกเครื่องบูตติดแน่ ๆ ความเร็วเต็มต้องไปเปิดโปรไฟล์ XMP เอง
ปิ๊บ,แต่ XMP ก็คือการโอเวอร์คล็อกแบบหนึ่ง บางเครื่องเปิดแล้วบูตไม่ขึ้น ถ้าเจอแบบนั้นให้เคลียร์ CMOS

# Phase 6 เลือกไดรฟ์ลง OS — เลือกดิสก์ลูกค้า
ปิ๊บ,หยุดก่อนขม! ลูกนั้นมีข้อมูลลูกค้าอยู่ ลงทับคือหายหมดและกู้ยากมาก
ปิ๊บ,ของแบบนี้พลาดครั้งเดียวคือจบเลย ไม่ใช่แค่เครื่องเสีย แต่ความเชื่อใจเสียด้วย

# Phase 7 อัปเกรด
ปิ๊บ,ดูกราฟสิ แท่งไหนเตี้ยสุดนั่นแหละคือคอขวด อัปตรงนั้นถึงจะรู้สึกว่าเร็วขึ้น
ปิ๊บ,ถ้าไปอัปชิ้นที่แท่งสูงอยู่แล้ว ลูกค้าจ่ายเงินแล้วไม่รู้สึกอะไรเลย แล้วเขาจะไม่กลับมาอีก
ปิ๊บ,บางทีคำตอบที่ถูกคือ "ยังไม่ต้องซื้ออะไรครับ" นะ

# SUMMARY
ปิ๊บ,เครื่องบูตเข้าวินโดวส์แล้ว แรมวิ่งเต็มความเร็วด้วย
ปิ๊บ,จำไว้นะ งานซ่อมที่ดีคือแก้ให้มันไม่กลับมาเป็นอีก ไม่ใช่แค่ทำให้มันหายวันนี้
```

## 12. สเปกโค้ด

```gdscript
# Scripts/MiniGame/PartBios/part_bios.gd
class_name PartBiosGame extends PartMinigameBase

enum Phase { INSPECT, BRIEFING, CHECK_HW, BOOT_ORDER, XMP, SAVE_EXIT, OS_INSTALL, UPGRADE }
enum ExitChoice { SAVE, DISCARD, LOAD_DEFAULT }
enum DriveId { SSD_EMPTY, HDD_CUSTOMER_DATA, USB_INSTALLER }

var boot_order: Array[StringName] = [&"usb", &"hdd", &"dvd", &"net"]
var xmp_enabled := false
var usb_removed := false
var needs_os_install := false

func boot_result() -> bool:
	# บูตผ่านเมื่อไดรฟ์ที่มีระบบอยู่อันดับต้น หรือ USB ถูกถอดออก
	return boot_order[0] == &"hdd" or usb_removed
```

* ค่าที่โชว์บนหน้าจอผูกกับ state จริง — `Label` อ่านจาก `boot_order` / `xmp_enabled` ตรง ๆ ไม่ใช่ข้อความตายตัว
* XMP ล้มเหลวแบบสุ่ม 20% ใช้ `randf() < 0.2` แล้วบังคับให้ผู้เล่นเคลียร์ CMOS (เชื่อมกับ Normal Part `cmos`)
* Phase 6 ข้ามได้ด้วย `needs_os_install` ที่ตั้งมาจากเคสลูกค้า
